# 디자인 만들기

디자인은 같은 덱을 다른 옷으로 그린다. 그래서 디자인을 하나 만들면 「도름스 탄생비화」 63장이 그 옷을 입고 바로 샘플이 된다.

## 레퍼런스에서 디자인을 뽑는 법 (가장 중요)

선생님이 "이 사이트·이 코드 느낌으로" 하고 레퍼런스를 주면 이렇게 한다. 도름스 운영진이 실제로 디자인을 옮길 때 쓰는 방법이다.

1. **렌더해서 본다.** 레퍼런스 코드를 글자로만 읽고 짐작하지 않는다. 로컬에서 띄우거나 주소를 브라우저로 열어 화면을 찍는다.
   움직임이 있으면 몇 장면을 찍는다. 화면을 보지 못했으면 "추정함" 이라고 선생님에게 밝힌다.
2. **디자인 요소만 적어 둔다(토큰).** `designs/<이름>/design.json` 과 CSS 변수로:
   - 색: 바탕 · 글자 · 흐린 글자 · 선 · 포인트 1~3개 (표식 색 `markColor` 는 포인트 색 하나)
   - 글꼴: 제목 · 본문 · 라벨(모노). 무료로 다시 나눌 수 있는 글꼴만(OFL 등)
   - 모양: 모서리 둥글기, 선 굵기, 그림자, 질감(그레인·격자·빗금)
   - 움직임: 등장 방식, 속도, 반복 모티프
   - 레퍼런스의 **문구·내용·로고는 가져오지 않는다.**
3. **구조는 내용에 맞게 다시 짠다.** 레퍼런스 화면의 배치를 그대로 베끼지 않는다. 각 배치(layout)가 보여 줘야 할 내용(숫자·연표·대비·인용…)이 가장 잘 읽히는 구조를 먼저 정하고, 그 위에 2번의 요소를 입힌다.
4. **여백을 만들지 않는다.** 빈 곳은 글자를 키워 채운다(AutoFit). 세로·가로로 넘치는 장이 없어야 한다.
5. **샘플로 확인한다.** `npm run dev` → `/?sample=dorms-story&design=<이름>` 에서 63장을 다 넘겨 본다. 표지·목차·숫자·연표·인용 카드·마무리 장은 꼭 본다.
6. **표식은 그대로.** 표식 색만 `markColor` 로 맞춘다. 표식을 가리는 CSS 를 쓰면 `npm run check:mark` 가 막는다.

## 파일

```
designs/<이름>/
  design.json      목록 정보 { id, name, summary, markColor, sample, maker, shelf, version, fonts }
  index.tsx        Design 객체(src/runtime/design.ts). renderBody · layouts · fitMax
  <이름>.css       모든 규칙을 .design-<이름> 안에서만 쓴다
  README.md        배치 표(언제 쓰나 · 어떤 칸을 읽나 · 샘플 몇 쪽)
```

- 처음 만들 때는 `designs/dorms-story` 를 본보기로 삼는다. 배치 이름(ch-hero, ch-timeline …)과 칸 읽는 법을 그대로 쓰면, 샘플과 다른 선생님 덱이 바로 새 디자인으로 그려진다.
- `designs/simulation-blueprint` 는 같은 배치에 전혀 다른 옷(검은 계기판 · 원형 도면)을 입힌 본보기다. 배치 코드를 다시 짜지 않고 토큰 · CSS · 장식 층으로 옷을 바꾸는 법을 보여 준다.
- `designs/index.ts` 에 한 줄 더하고 `npm run catalog` 를 돌린다.
